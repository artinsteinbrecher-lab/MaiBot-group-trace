# 麦麦群聊寻迹

[![CI](https://github.com/artinsteinbrecher-lab/MaiBot-group-trace/actions/workflows/ci.yml/badge.svg)](https://github.com/artinsteinbrecher-lab/MaiBot-group-trace/actions/workflows/ci.yml)

麦麦群聊寻迹是一个独立的 MaiBot 插件。你可以给麦麦一段线索，让她去指定群聊里寻找相关历史；也可以用一句自然语言创建复合关键词观察规则，在后续出现相关讨论时收到私聊提醒。

它不依赖“麦麦写书”或其他日报插件，也不会修改 MaiBot 主程序。

## 它能做什么

- 根据文字线索检索指定 QQ 群的历史消息。
- 回复一条文字消息后，把这条消息当作寻迹线索。
- 使用关键词、别名、排除词、正则、时间窗口和出现次数组成观察规则。
- 先用本地规则筛选，再选择性调用模型做语义复核。
- 使用 MaiBot 已有的嵌入模型寻找“说法不同但意思接近”的历史消息。
- 在回答中保留时间、成员和证据编号，证据不足时明确说明。
- 可选连接一个返回 JSON 的外部查询接口；查询失败不会影响群聊检索和监控。

## 安装

1. 下载 [`MaiBot-group-trace-v0.1.0.zip`](dist/MaiBot-group-trace-v0.1.0.zip) 并解压。
2. 把整个 `MaiBot_group_trace` 文件夹放进 MaiBot 的 `plugins/` 目录。
3. 启动 MaiBot，或等待插件系统自动热重载。
4. 打开 WebUI 的插件设置，找到“麦麦群聊寻迹”。
5. 至少填写：
   - `管理员 QQ`：允许使用寻迹和监控命令的人。
   - `允许访问的群聊`：插件可以读取的 QQ 群号。

这两个名单默认都是空的。没有主动填写前，插件不会读取任何群聊，也不会允许任何人跨群查询。

## 最快上手

查看插件当前能访问哪些群：

```text
/寻迹群列表
```

根据文字寻找历史消息：

```text
/寻迹 123456789 找一下之前讨论 DSV4F 输出限制和 max_tokens 的内容
```

也可以先回复一条文字消息，再发送：

```text
/寻迹 123456789
```

创建观察规则草稿：

```text
/监控创建 123456789 帮我关注 DSV4F 输出限制，提到 64K、384K 或 max_tokens 时提醒，价格讨论不用管
```

麦麦会先把理解结果发给你。确认无误后发送：

```text
/监控确认
```

规则不会在模型生成草稿后直接生效，必须由创建者确认。

## 其他命令

```text
/监控列表
/监控暂停 规则编号
/监控恢复 规则编号
/监控删除 规则编号
/监控取消
/寻迹帮助
```

## 模型设置

插件设置中可以填写三个 MaiBot 模型任务名：

- 需求理解任务：理解自然语言规则和寻迹目标。
- 事实复核任务：判断命中是否相关，并根据证据回答。
- 嵌入任务：默认使用 MaiBot 的 `embedding` 任务。

前两个默认使用 MaiBot 的 `utils` 任务；即使旧配置留空，也会安全回退到 `utils`，不会误用嵌入任务。插件不在自己的配置中保存模型供应商、地址或密钥。

## 需要知道的限制

- 插件只能查询 MaiBot 数据库里已经存在的消息；安装以前且没有被保存的记录无法找回。
- 群聊名称相同并不代表是同一个群，因此命令和白名单都使用群号。
- 语义检索能提高召回率，但最终答案仍然受现有证据质量影响。
- 外部查询是可选补充，不能证明群聊里说过相同内容。
- 图片和截图识别尚未进入 0.1.0；首版以文字、回复文字和转发后的可读文本为主。
