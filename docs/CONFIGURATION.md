# 配置说明

日常设置直接在 MaiBot WebUI 中完成。插件使用强类型配置模型，首次加载时会由 Runner 生成 `config.toml`，以后新增字段也会自动补齐默认值。

## 必填的两个名单

### 管理员 QQ

只有名单中的用户可以：

- 查询指定群历史。
- 创建、确认、暂停、恢复和删除观察规则。
- 查看允许访问的群聊。

名单为空时，所有管理命令都会拒绝执行。

### 允许访问的群聊

只有名单中的群会被观察和检索。名单为空时，插件不会读取任何群聊。

## 关键词观察

- `启用实时观察`：关闭后保留规则，但不再检查新消息。
- `每群上下文消息上限`：用于跨多条消息组合判断，只保存在内存中。
- `提醒证据条数`：私聊提醒里最多展示的群消息数量。
- `启用语义复核`：本地规则命中后，再让事实复核模型排除引用、玩笑和同名无关内容。
- `命中后查询外部资料`：需要同时启用并配置外部资料查询。

纯语义规则不会被保存。每条实时规则至少需要一个关键词或正则，避免模型检查群里的每一句话。

## 群聊寻迹

- `默认检索天数`：用户没有说明时间时使用。
- `历史消息上限（单页）`：单页从 MaiBot 数据库读取的消息数量；插件会从最新往回逐页扫描，直到覆盖完整时间范围。
- `扫描消息上限`：单次寻迹累计扫描的消息总数上限。高流量群（日均数千条）建议调大，否则时间范围可能覆盖不全；达到上限时回答中会明确提示。
- `本地候选数量`：先用文字相关性缩小范围，再调用嵌入任务。
- `查询证据条数`：最终答案能够引用的消息上限。
- `前后上下文条数`：给匹配消息补齐附近对话。
- `启用嵌入语义检索`：关闭后只使用本地文字相关性。
- `启用本地关键词索引`：把白名单群的文本消息写入插件本地索引，寻迹时按关键词直查（类似 QQ 的聊天记录搜索）；索引未覆盖的更早时段自动分页扫描补齐。关闭后回退为纯扫描。
- `索引保留天数`：默认 180 天；超期消息和移出白名单群的消息自动清理。

## 模型任务

`需求理解任务` 和 `事实复核任务` 接受 MaiBot 模型管理页里的任务名称，默认使用 `utils`。旧配置即使留空，也会安全回退到 `utils`，避免被 MaiBot 解析成嵌入任务。

`嵌入任务` 默认是 `embedding`，通常无需修改。

## 外部资料查询

0.1.0 使用通用 JSON GET 接口，不绑定搜索供应商。

假设接口地址是：

```text
https://example.com/search?q=关键词
```

返回：

```json
{
  "results": [
    {
      "title": "标题",
      "url": "https://example.com/article",
      "snippet": "摘要",
      "published_at": "2026-08-15"
    }
  ]
}
```

对应设置：

- 接口地址：`https://example.com/search`
- 查询参数名：`q`
- 结果数组路径：`results`
- 标题字段：`title`
- 链接字段：`url`
- 摘要字段：`snippet`
- 时间字段：`published_at`

接口也可以在地址中使用 `{query}`：

```text
https://example.com/search/{query}
```

API 密钥存放在当前安装实例的 `config.toml` 中。不要把真实密钥提交到 Git 仓库或发送到公共群聊。

## 手动配置

更喜欢编辑文件时，可以参考根目录的 `config.example.toml`。通常不需要复制它，WebUI 会生成并维护实际的 `config.toml`。
